# Production goals, dependency graph, and progression advice

The server owns planning in `apps/server/src/planning.ts`. It reads the same `recipe`, `cycleMs`, `effectiveLevel`, `qualityChance`, `buildCost`, `landCost`, `capacityReason`, `marketPrice`, and purchase-allowance rules used by the economy. The planner never advances time, consumes resources, changes random state, creates orders, or constructs facilities.

`planProduction(game, corporation, {regionId, facilityId?, quantity?, now?})` returns a versioned `ProductionPlan`. The authenticated `GET /api/plan` route supplies the caller's corporation. An omitted facility uses that region's persisted pinned goal; an explicit new facility defaults to one, independently of the old pin. Quantity is a whole number from 1 to 100. Server actions `goal.pin` and `goal.clear` persist selection separately from this read-only module.

A pin records its current facility count and a target of that count plus the requested quantity. `pinnedGoal` reports current/target counts, remaining construction and completion. Parameterless goal reads quote only the remaining quantity; a completed pin returns `goal: null` with `pinnedGoal.completed: true`, so the UI can celebrate and clear it. An explicit facility query remains an independent what-if quote. The target describes owned facilities, so demolishing them can increase what remains; at most 100 are quoted per valid construction batch. Legacy pins infer their baseline from recorded construction timestamps.

Each goal contains current construction capital, land use and extra-land cost, missing materials, locks, and regional/global prerequisites. A headquarters in another region satisfies retail access. Research and regional facility caps remain blockers. Material rows include live NPC quotes and the remaining hourly allowance where NPC buying is allowed; these are purchase options, not assumed automatic purchases. Building and unlocking still use ordinary server actions and their validation.

The graph connects actual resource inputs and outputs with distinct construction, technology-development, and random-discovery edges. Missing prerequisites expand into their own construction bills. Technology development includes a regional blueprint, materials and capital; upgraded technology combines three items of the previous tier. Research discovery edges deliberately have no guaranteed quantity. A global prerequisite owned elsewhere is marked `available-globally` rather than suggested as another mandatory build. Graph output is bounded to 190 nodes and ten dependency levels; `truncated` tells the client when this limit is reached.

Factory groups combine owned instances by facility type. Their input choices reflect current plus-input preferences; output rates use actual cycle speed and quality probability, including efficiency relic conversion. The graph distinguishes paused, starved, capacity-stopped and producing groups. A shortage includes stock, aggregate next-cycle demand, full-speed production/consumption, a depletion estimate, and actual stalled facility IDs. Shared stock insufficient for two independently runnable factories is identified without falsely saying either is already stalled. Construction and procurement suggestions are navigation metadata, not automatic economic actions.

Goal times are explicitly qualified rate estimates. They include one current cycle wait and expected quality yields. Missing land, locked resources, absent prerequisites, insufficient capital with no active regional cash-production rate, capacity stops, starved producers, non-accumulating stock or input supplies that would run out block an overall ETA. Existing input buffers may support a short estimate even when sustained input production is lower than consumption. Estimates never assume future player fills, manual NPC sales, retail income, unclaimed deliveries or purchases. Automatic cash rates are considered within the selected region; global current cash is always available. Estimates over one year are omitted. This version does not clone-simulate future outcomes or reveal committed random results.

`onboardingProgress(game, corporation, now?, regionId?)` is a lightweight snapshot helper. It avoids graph traversal and returns stage, milestone steps, recommended screen and navigation priorities. The stages are first production, logistics, research, regional development and space. Advice uses actual holdings, installed technology, shared office status and completed account activity. Advanced navigation remains available; advice does not create artificial gameplay locks. Steps expose both `done`/`action` for the planner and `completed`/`screen` for compact onboarding views.

The client consumes this server data instead of recreating economy formulas. `PlannerAction` values supply labels, existing screen IDs and optional payloads; executable actions still go through normal authenticated action handling. Neither the graph nor the progression response includes another corporation's private state.

`tests/planning.test.ts` validates immutable/read-only behavior, policy-adjusted costs, regional pins, quantity validation, global headquarters access, real prerequisite/development graphs, locks/land/caps, NPC allowance quotes, technology-adjusted rates, missing-capital and starved-chain ETAs, shared scarce inputs, quality/efficiency/plus preferences, bounded graph references, progression stages and private-corporation isolation.
